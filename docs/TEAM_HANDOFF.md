# EasyAccess 团队交接说明

更新日期：2026-09-27
当前交接版本：Android `0.9.0`
仓库：`https://github.com/anshengrui/AIC.git`

## 1. 先读结论

EasyAccess 当前已经是一个可安装、可在 Android 真机运行、可调用云端多模态模型的核心原型，适合由另一位队员继续开发和准备初赛演示；它还不是完整的竞赛提交包，也不是商业发布版本。

已经完成的核心价值闭环是：

```text
用户选择/输入目标
  -> Android 观察当前界面
  -> 固定规则快速命中，或发送单帧截图到云端多模态模型
  -> 模型返回结构化页面、目标和下一步
  -> 本地坐标/置信度/风险规则复核
  -> 高亮 + 文字 + 语音提示
  -> 页面变化后重新观察，直到完成或安全停止
```

交接后的首要工作不是继续无限增加 App 操作，而是按照规格书补齐初赛可验收证据：正式 Mock Demo、30 组样例、指标、对比实验、软件说明书、视频和 PPT。

## 2. 事实来源和范围差异

根目录的 `EasyAccess_项目交接与执行规格书_v1.0.pdf` 是产品定位、数据契约、验收标准和安全边界的单一事实来源。该 PDF 及参赛承诺书属于本地竞赛资料，当前被 `.gitignore` 排除，不进入公开仓库；负责人需要通过可信渠道单独发给队友。

规格书要求三周版以 Web + 自制模拟界面为正式比赛演示，不依赖第三方 App 登录，不接管真实手机。当前仓库在保留 Web Mock 闭环的基础上，额外实现了 Android 实时界面辅助。这个扩展经过用户确认，且仍坚持“不自动点击、只提示和高亮”的安全边界。

因此后续展示建议分成两层：

1. 正式可复现证据：Web Mock、结构化数据、反馈、风险规则、离线测试。
2. 产品落地亮点：Android 真机实时辅助、云端模型和语音/高亮体验。

不要只演示真实淘宝、支付宝或微信；比赛现场账号、网络和第三方界面变化不可控。

## 3. 当前架构

| 层 | 目录/组件 | 当前职责 |
| --- | --- | --- |
| Web 演示 | `frontend/` | 上传截图、选择模式、显示手机预览、高亮、步骤卡和四类反馈 |
| API | `backend/app/api/` | 会话、图片校验、分析、反馈、风险确认、报告和健康检查 |
| 模型适配 | `backend/app/llm/` | OpenAI 兼容多模态请求、Prompt、结构解析、一次修复和降级 |
| 确定性逻辑 | `backend/app/services/` | Mock、会话状态和风险规则 |
| Android | `android/app/src/main/` | 无障碍界面观察、本机文字识别、任务规则、云端 AI、覆盖层和语音提示 |
| 云端入口 | `backend/server.py` | 阿里云函数计算 Web 函数启动入口，监听 `9000` |
| 部署 | `Dockerfile`、`backend/requirements-fc.txt` | 容器或 ZIP 部署依赖 |

模型供应商通过 OpenAI 兼容接口隔离。当前云端使用阿里云百炼 `qwen3.8-flash`，关闭深度思考以降低界面定位等待时间。

## 6. 模型和数据的准确表述

### 当前使用的方法

- 调用成熟多模态大模型 API，不训练基础模型。
- 使用任务 Prompt 让模型输出页面、元素、归一化坐标、下一步、置信度和风险线索。
- 使用 Pydantic Schema 校验、一次结构修复、低置信度阈值和安全降级。
- 使用本地固定流程、状态信息和风险规则约束模型。
- Android 优先用确定性规则获得低延迟；规则无法处理的新页面再调用多模态模型。

当前没有完成模型微调，因此演讲或材料中不要说“已经训练/微调出模型”。可以说后续在合规标注数据达到规模后评估 LoRA 或提示微调，但初赛阶段重点是“模型适配 + 结构化约束 + 算法规则融合”。

### 当前数据来源

- Web 内置界面为团队自制的通用模拟 UI。
- 真机测试来自负责人自己的测试手机和已登录应用，仅做即时推理，默认不保存、不进入仓库。
- 当前没有从网上批量抓取淘宝、支付宝、微信截图，也没有可宣称为训练集的第三方数据集。
- 后续离线数据应优先使用自制模拟界面、团队自有并脱敏的截图、取得同意的志愿者截图；记录来源、授权、用途和删除策略。

## 7. 队友首次接手步骤

### 7.1 需要队友准备

1. GitHub 账号，并由仓库负责人添加协作者权限。
2. Windows 电脑；Python 3.11/3.12、Node.js、JDK 17、Android Studio/SDK。
3. 一台 Android 8.0 以上测试手机；如测试真实流程，安装淘宝、支付宝和微信测试环境。
4. 从负责人处私下获取规格书 PDF；不要要求负责人把 API Key 发到聊天或 GitHub。
5. 如需调用真实模型，申请自己的百炼 Key，或由负责人创建最小权限的云端协作方式。
6. 获取最新竞赛通知、提交模板、截止时间、视频时长和文件大小限制；仓库只记录通用准备项，不能替代官方通知。

### 7.2 克隆和运行

```powershell
git clone https://github.com/anshengrui/AIC.git
Set-Location AIC
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r backend\requirements.txt
Copy-Item .env.example .env
python -m uvicorn app.main:app --reload --app-dir backend
```

另开终端：

```powershell
Set-Location frontend
npm install
npm run dev
```

Android 本地创建 `android/local.properties`：

```properties
sdk.dir=你的Android SDK路径
EASYACCESS_API_BASE_URL=https://你的云函数域名/api
EASYACCESS_API_TOKEN=与云端一致的客户端令牌
```

该文件被 Git 忽略。不要把真实值复制到 Issue、聊天截图、提交记录或 APK 发布说明中。

## 10. Git 协作约定

```powershell
git switch main
git pull --ff-only
git switch -c feature/简短任务名
# 修改并验证
git add 指定文件
git commit -m "feat: 简短说明"
git push -u origin feature/简短任务名
```

- 不在两个电脑上直接同时修改 `main`。
- 每个提交只处理一个主题；提交前看 `git diff --cached`。
- 不使用 `git reset --hard` 覆盖队友改动。
- 大视频、APK、云函数 ZIP 优先放 GitHub Release 或团队网盘，不放普通 Git 历史。
