# Android 第一步：实时界面感知验证

## 目标

构建一个最小可安装 Android 原型，通过无障碍服务实时观察淘宝、支付宝和微信暴露的界面节点，并在目标控件上绘制高亮提示框。

本阶段验证的是 EasyAccess 的“眼睛”，不验证模型推理能力。

## 支持范围

| 应用 | 包名 | 初赛目标任务 |
| --- | --- | --- |
| 淘宝 | `com.taobao.taobao` | 查看订单物流 |
| 支付宝 | `com.eg.android.AlipayGphone` | 找到乘车码入口 |
| 微信 | `com.tencent.mm` | 搜索联系人并打开聊天页 |

## 已实现

- Android 应用工程骨架；
- 无障碍服务声明与用户开启入口；
- 三个目标应用的白名单；
- 页面切换、内容变化、滚动事件监听；
- 600ms 防抖后的控件树采集；
- 控件文字、描述、类型、可点击状态与屏幕坐标提取；
- 密码和输入框文字最小化采集；
- 最近一次观察结果仅内存保存；
- 基于常见关键词的蓝色悬浮高亮框；
- 调试页面展示当前应用、采集时间和控件摘要。

## 待验证

- Gradle 依赖能否在当前电脑下载并完成构建；
- 不同 Android 版本上的权限页面差异；
- 三个目标 App 最新版本实际暴露的节点数量；
- 高亮框在状态栏、全面屏和不同分辨率下的位置误差；
- WebView、自绘页面和安全页面的缺失比例。

## 验收方法

1. 安装 debug APK 并开启 EasyAccess 无障碍服务。
2. 分别打开淘宝、支付宝和微信。
3. 每个应用至少切换三个页面并记录节点数。
4. 检查文字、控件坐标和实际页面是否一致。
5. 检查高亮框能否覆盖目标控件且不阻止用户点击。
6. 对读取不到的页面记录 App 版本、页面名称和截图兜底需求。

## 下一步

第一阶段真机验证通过后，将新增统一的 `PageObservation` 接口，把经过脱敏的控件树发送给现有 FastAPI 后端，并先用 Mock 规则返回下一步目标。
