# EasyAccess 初赛提交材料清单

更新日期：2026-09-27
依据：项目规格书第 10、12 节及当前仓库进展

> 本清单是团队内部准备基线。报名平台的文件格式、大小、命名、截止时间和签字要求必须以最新官方通知为准，由队友补充核对。

## 一、必须准备的五项核心材料

| 材料 | 必须包含 | 当前状态 | 建议负责人 |
| --- | --- | --- | --- |
| 软件说明书/操作手册 | 需求、目标用户、功能、架构、部署、安装、操作步骤、异常处理、隐私、安全与限制 | 未形成最终稿；仓库文档可作为素材 | 成员 B 主笔，A 核对技术 |
| 核心算法说明 | 页面理解、结构化输出、状态机、步骤评分、用户画像、风险规则、模型与规则分工 | 有代码和规格，未形成独立答辩稿 | 成员 A |
| 测试报告 | 数据来源、标注规范、指标、对比实验、失败案例、设备/模型/版本、复现方法 | 有单轮真机记录，缺 30+ 样例和正式统计 | 成员 A 主笔，B 做用户测试 |
| 3 分钟演示视频 | 完整故事线、异常恢复、风险拦截、完成结果、算法指标 | 未制作 | 成员 B，双方出镜/配音 |
| 答辩 PPT | 痛点、用户、创新、架构、算法、产品、测试、价值、限制、计划 | 未制作 | 成员 B 主笔，A 准备技术页 |

## 二、建议一并准备的提交附件

- 项目摘要和关键词。
- 团队成员、指导教师、学校/学院信息。
- 参赛选手承诺书及官方要求的签字/盖章文件。
- GitHub 仓库地址和固定提交哈希。
- Android Debug/Release APK 或 GitHub Release 下载地址。
- Web Mock 本地启动包或稳定演示地址。
- 一页系统架构图、一页核心算法流程图、一页安全边界图。
- 数据来源与授权说明、隐私说明、第三方模型/API 使用说明。
- 现场备用：离线 Mock、缓存样例、视频副本、PPT/PDF 双版本。

## 三、软件说明书建议目录

1. 项目概述：背景、痛点、目标用户、产品定位。
2. 功能说明：任务输入、页面理解、高亮/语音、反馈、偏航恢复、风险干预。
3. 系统架构：Web、FastAPI、模型适配、确定性规则、Android、云端部署。
4. 大模型方法：为什么使用多模态模型、输入输出、结构化校验、降级和成本控制。
5. 安装部署：Windows 本地、Mock 模式、真实模型、Render 云端服务、Android 构建。
6. 用户操作：首次授权、选择任务、跟随提示、重复/暂停/结束、异常处理。
7. 数据与隐私：数据来源、截图生命周期、脱敏、日志最小化、密钥管理。
8. 安全边界：不自动点击、不代替支付/转账/授权/删除/发送消息。
9. 测试和指标：环境、样例、指标定义、结果、失败案例。
10. 已知限制和后续规划。

软件说明书不能只写“如何点按钮”；它同时承担软件设计、部署、操作、安全和限制说明。

## 四、核心算法说明必须讲清楚

### 4.1 大模型负责

- 理解复杂页面语义和口语目标。
- 识别按钮、标签、输入框和相对关系。
- 将用户目标拆成下一步候选。
- 在页面变化或误操作后解释当前状态。
- 根据辅助模式生成简化说明。

### 4.2 确定性算法负责

- Schema 校验和枚举约束。
- 坐标范围、面积和置信度检查。
- 状态推进、页面切换和缓存失效。
- 固定高频任务的快速路径。
- 风险规则、确认、停止和安全降级。

### 4.3 当前不能虚构的内容

- 没有训练基础大模型。
- 没有完成模型微调。
- 没有大规模真实用户数据集。
- 单轮真机成功不能写成统计准确率。

## 五、数据集和测试报告待办

### 5.1 至少 30 组样例

建议建立五类任务，每类至少 6 组：

1. 关闭自动续费。
2. 判断隐私权限。
3. 校园表单。
4. 信息查询/导航。
5. 高风险与偏航恢复。

每组至少记录：

```text
case_id
source_type（自制/团队自有脱敏/志愿者授权）
task_text
mode
page_type
target_bbox
correct_action
risk_level
expected_status
consent_or_license
```

禁止提交含账号、姓名、头像、订单号、地址、聊天、银行卡、验证码和支付信息的原始截图。

### 5.2 必须统计的指标

| 指标 | 规格书建议目标 |
| --- | --- |
| 目标元素命中率 | >= 80% |
| 下一步正确率 | >= 85% |
| 风险召回率 | >= 95% |
| 任务完成率 | >= 80% |
| 偏航恢复率 | >= 80% |
| 结构化输出成功率 | >= 98% |
| 平均响应时间 | 演示环境 <= 8 秒 |

结果达不到目标时如实报告，并给出失败类型和改进方案，不筛除失败样例。

### 5.3 三组对比实验

1. 大模型自由回答 vs 结构化观察 + 规则层。
2. 统一说明 vs 老年/低视力个性化说明。
3. 正常路径 vs 主动注入一次误操作。

## 六、正式三条 Demo

### Demo 1：关闭自动续费

- 展示任务理解、目标高亮、跨页面状态。
- 主动点错一次，展示偏航恢复。
- 在确认页面解释后果并要求二次确认。
- 最后显示完成报告。

### Demo 2：隐私权限

- 展示权限与当前任务是否相关。
- 通讯录/身份信息等高风险权限必须解释并确认或建议拒绝。

### Demo 3：校园表单

- 展示字段解释、缺失材料提醒和完成验证。
- 不代替用户提交真实个人信息。

正式 Demo 使用团队自制模拟手机界面，真实第三方 App 只作为额外落地展示。

## 七、3 分钟视频建议时间线

| 时间 | 内容 |
| --- | --- |
| 0:00-0:20 | 用户痛点和任务输入 |
| 0:20-1:00 | 正常识别、高亮和语音引导 |
| 1:00-1:35 | 用户故意点错，系统重新规划 |
| 1:35-2:10 | 敏感动作风险拦截和二次确认 |
| 2:10-2:30 | 任务完成报告 |
| 2:30-3:00 | 多模态模型 + 结构化算法 + 指标与价值 |

录屏前关闭通知预览，使用模拟账号/页面，禁止出现真实聊天、订单、地址、手机号、余额、银行卡或 API Key。

## 八、PPT 建议 10 页

1. 标题与一句话定义。
2. 老年人/低视力用户的数字操作痛点。
3. 产品流程和核心体验。
4. 系统架构。
5. 多模态页面理解和结构化输出。
6. 状态机、步骤评分、风险规则和个性化。
7. Web Mock + Android 真机效果。
8. 数据、指标、对比实验和失败案例。
9. 创新性、应用价值与竞品差异。
10. 安全边界、当前限制和下一步。
